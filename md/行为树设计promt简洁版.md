# 行为树技术规范

## 节点类型

### 组合节点（控制流程）
- **顺序节点**：按顺序执行子节点，所有子节点成功才返回成功
- **选择节点**：按顺序执行子节点，任一子节点成功即返回成功
- **并行节点**：同时执行所有子节点，根据策略（require_all/require_one）决定结果

### 条件节点（检测判断）
- **OCR条件节点**：检测指定区域的文字内容
- **图像条件节点**：匹配指定区域的图像模板
- **颜色条件节点**：检测指定区域的颜色
- **数字条件节点**：识别数字并与阈值比较
- **变量条件节点**：判断黑板变量是否满足条件

### 动作节点（执行操作）
- **按键动作节点**：模拟键盘按键
- **点击动作节点**：模拟鼠标点击（支持单击/双击/长按/无限点击）
- **移动动作节点**：移动鼠标位置（支持拖拽）
- **滚轮动作节点**：鼠标滚轮滚动
- **延时动作节点**：延时等待（非阻塞）
- **设变量动作节点**：设置黑板变量
- **脚本动作节点**：执行脚本文件
- **代码动作节点**：执行外部代码
- **报警动作节点**：播放报警音频

## 重要特性

### 黑板变量
- 最后检测位置：所有检测节点成功后自动保存检测位置（绝对坐标）
- 最后数字值：数字检测节点保存识别的数字值
- 动作节点可通过"点击最近检测点"选项读取黑板位置

### 装饰参数
- **重试次数**：失败重试次数（-1表示无限重试）
- **重复次数**：重复执行次数（-1表示无限循环）
- **超时时间**：超时时间（毫秒，0表示不限时）
- **结果取反**：结果取反（条件节点）
- **检测间隔**：检测间隔（条件节点，默认300ms，最小30ms）

### 执行规则
1. 组合节点的子节点按连接顺序执行
2. 条件节点和动作节点支持子节点串联执行
3. 检测节点成功后可保存位置到黑板
4. 点击节点可读取黑板位置进行点击

### 节点选择原则
- 需要按顺序执行多个步骤 → 使用顺序节点
- 需要尝试多种方案，任一成功即可 → 使用选择节点
- 需要同时监控多个条件 → 使用并行节点
- 检测文字内容 → 使用OCR条件节点
- 检测图标/图像 → 使用图像条件节点
- 检测颜色 → 使用颜色条件节点
- 检测数值 → 使用数字条件节点
- 点击操作 → 使用点击动作节点
- 按键操作 → 使用按键动作节点
- 等待操作 → 使用延时动作节点

## 使用示例

### 示例1：简单场景

**用户填写的场景描述：**
```
场景目标：自动点击屏幕上的"开始"按钮
操作步骤：
1. 检测屏幕上是否出现"开始"文字
2. 如果检测到，点击该位置
3. 等待1秒
判断条件：检测"开始"文字是否存在
循环需求：无限循环执行
```

### 示例2：复杂场景

**用户填写的场景描述：**
```
场景目标：游戏自动战斗，当血量低于30%时自动使用药品
操作步骤：
1. 检测屏幕右上角的血量数字
2. 判断血量是否小于30
3. 如果小于30，按下快捷键"1"使用药品
4. 等待2秒后继续检测
判断条件：血量数字是否小于30
循环需求：无限循环执行
```
