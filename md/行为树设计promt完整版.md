### 3.2 节点选择指南

**AI应根据以下规则选择合适的节点类型：**

#### 组合节点选择规则：

```
使用顺序节点的场景：
- 需要按固定顺序执行的任务序列
- 所有步骤都必须成功才能继续
- 流程化的自动化操作

使用选择节点的场景：
- 多种方案尝试，任一成功即可
- 容错处理，提供备选方案
- 条件分支选择

使用并行节点的场景：
- 需要同时监控多个条件
- 并行执行独立任务
- 多资源同时检测
```

#### 条件节点选择规则：

```
使用OCR条件节点的场景：
- 检测界面文字内容
- 识别按钮文字
- 验证文本状态

使用图像条件节点的场景：
- 检测特定图标
- 识别按钮状态
- 匹配界面元素

使用颜色条件节点的场景：
- 检测状态指示灯颜色
- 识别特定颜色区域
- 判断进度条状态

使用数字条件节点的场景：
- 检测数值状态
- 判断资源数量
- 监控计数器

使用变量条件节点的场景：
- 流程控制条件
- 状态机切换
- 计数器判断
```

#### 动作节点选择规则：

使用按键动作节点的场景：

### 3.3 设计规范

**AI生成的设计方案必须遵循以下规范：**

```
1. 节点命名规范：
   - 使用有意义的名称，如"检测登录按钮"、"点击确认"
   - 避免使用"节点1"、"节点2"等无意义名称

2. 参数配置规范：
   - 所有坐标参数必须明确说明是固定坐标还是动态获取
   - 时间参数必须使用毫秒为单位
   - 检测区域必须明确指定坐标范围

3. 执行顺序规范：
   - 组合节点的子节点执行顺序必须明确
   - 条件节点和动作节点的串联执行必须符合逻辑

4. 容错处理规范：
   - 关键操作必须设置重试机制
   - 必须考虑超时情况
   - 必须说明失败后的处理方式

5. 数据传递规范：
   - 使用黑板变量传递数据时，必须明确变量名
   - 检测节点保存位置时，默认使用"最后检测位置"
   - 点击节点读取位置时，必须设置"点击最近检测点"选项

6. 性能优化规范：
   - 条件检测节点应设置合理的检测间隔
   - 避免不必要的全屏检测
   - 合理使用延时节点控制执行节奏
```

### 示例场景：游戏自动登录

#### 场景描述：

```
应用场景概述：
- 场景类型：游戏自动化

- 特殊要求：需要处理多种登录方式，支持失败重试

操作流程描述：
步骤1：检测登录界面
  - 操作类型：检测
  - 操作对象：文字"登录"
  - 操作位置：屏幕中央区域
  
步骤2：选择登录方式
  - 操作类型：检测+点击
  - 操作对象："账号登录"按钮
  - 操作位置：检测到的位置
  
步骤3：输入账号密码
  - 操作类型：点击+按键
  - 操作对象：输入框
  - 操作位置：账号输入框、密码输入框
  
步骤4：确认登录
  - 操作类型：点击
  - 操作对象："确认"按钮
  - 操作位置：检测到的位置
  
步骤5：等待进入游戏
  - 操作类型：检测
  - 操作对象：游戏主界面特征
  - 操作位置：全屏

条件与分支：
条件1：检测到"账号登录"按钮
  - 满足条件时：点击并输入账号密码
  - 不满足条件时：尝试其他登录方式

循环与重复：
循环类型：□ 条件循环
循环内容：整个登录流程
停止条件：成功进入游戏主界面或重试3次失败
```

### 4.3 容错机制
